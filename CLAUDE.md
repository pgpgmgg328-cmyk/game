# CLAUDE.md — «Сквиши Клавиши: Мерж до Пробела»

## Кто ты и что мы делаем

Ты ведущий разработчик HTML5-игр. Мы делаем казуальную 2D-игру для детей 6–12 лет для платформы Яндекс Игры: физический мерж мягких клавиш-персонажей. Полный диздок подключён здесь: @docs/GAME_DESIGN.md

Если задача противоречит диздоку или правилам ниже, остановись и спроси.

Владелец проекта не программист. Отвечай по-русски, объясняй решения коротко и простыми словами. В конце каждой задачи пиши три вещи: что сделано, как проверить руками, что дальше.

## Стек (не менять без согласования)

- TypeScript (strict), Vite, Phaser 3 (последняя версия 3.x, не Phaser 4: по третьей версии намного больше примеров) со встроенной физикой Matter.js.
- Vitest для юнит-тестов чистой логики, Playwright для скриншотов и smoke-тестов, ESLint + Prettier.
- Никаких других рантайм-зависимостей без согласования: важны размер сборки и скорость загрузки.
- Графика процедурная: клавиши, лица, фоны, частицы рисуются кодом (Phaser Graphics или canvas) и превращаются в текстуры при загрузке мира.
- Звук синтезируется через WebAudio (допустим ZzFX, лицензия MIT).
- Шрифт — локальный woff2 с лицензией OFL и кириллицей (например, Nunito), лежит в проекте.
- Никаких внешних CDN, Google Fonts и сетевых запросов.
- В vite.config обязательно `base: './'`, иначе на хостинге Яндекса сломаются пути к ассетам.

## Команды

- `npm run dev` — локальный запуск без SDK (LocalPlatform с моками).
- `npm run dev:ya` — запуск с моками SDK от Яндекса: `npx @yandex-games/sdk-dev-proxy -h localhost:5173 --dev-mode=true`.
- `npm run build` — прод-сборка в `dist/`.
- `npm run check` — typecheck + lint + unit-тесты.
- `npm run e2e` — Playwright: скриншоты на всех целевых разрешениях + smoke.
- `npm run soak` — бот играет 10 минут; проверяем, что нет ошибок в консоли и роста памяти.
- `npm run moderation` — скрипт самопроверки сборки (описан ниже).
- `npm run zip` — архив для консоли: `release/squishy-keys-vX.Y.Z.zip`.

Если какой-то команды ещё нет, создай её при первой необходимости.

## Архитектура

```
src/
  main.ts                 конфиг Phaser, масштабирование, запуск
  platform/
    Platform.ts           интерфейс: init, ready, gameplayStart/Stop, onPause/onResume,
                          showInterstitial, showRewarded, load/save, lang, auth,
                          purchases, leaderboard, serverTime, flags, review, shortcut
    YandexPlatform.ts     ЕДИНСТВЕННОЕ место, где вызывается ysdk
    LocalPlatform.ts      моки: реклама = заглушка на 1 с, сохранения = localStorage
    index.ts              выбирает Yandex, если есть window.YaGames, иначе Local
  core/                   чистая логика без Phaser: мерж, экономика, апгрейды,
                          альбом, дейлики, сохранения и миграции; покрыта тестами
  game/scenes/            Boot, Preload, Menu, Game, Result, Album, Upgrades,
                          Shop, Worlds, Leaderboard, Settings, Pause
  game/objects/           Keycap, Jar, DangerLine, Particles
  game/art/               процедурная отрисовка клавиш, лиц, фонов по данным тем
  audio/                  синтез звуков, музыка, менеджер громкости и mute
  themes/                 данные миров: world1-classic.ts, world2-candy.ts, world3-space.ts
  i18n/                   ru.json, en.json
  config/balance.ts       все числа баланса + дефолты для remote flags
  config/iap.ts           id покупок и что они дают
tests/  e2e/  scripts/ (zip.ts, moderation-check.ts)
docs/   GAME_DESIGN.md, PROGRESS.md, store/ (тексты для консоли), yandex/ (документация)
purchases-catalog.json    каталог покупок для dev-режима SDK
```

Правила архитектуры:

- Любой вызов SDK идёт только через `platform/`. Сцены знают только интерфейс Platform.
- Контент мира (имена форм, надписи, цвета, лица, параметры звука, модификаторы физики) хранится только как данные в `themes/`. Новый мир — это новый файл данных без правок движка. Это наш «движок под тренды»: мир под новую волну должен собираться за день.
- Все числа баланса лежат только в `config/balance.ts`.
- `core/` не импортирует Phaser, поэтому логику можно тестировать без браузера.

## Обязательные требования Яндекс Игр (нарушение = отказ модерации)

Первоисточник — `docs/yandex/`. Если там пусто, скачай актуальные страницы документации (требования к игре, SDK: подключение, разметка геймплея, данные игрока, реклама, покупки, лидерборды, события, окружение, отзывы, ярлык, remote config, локальный запуск). Не выдумывай API: если не уверен в сигнатуре метода, открой документацию.

### SDK

- В `<head>` index.html: `<script src="/sdk.js"></script>`. Путь именно такой, файл sdk.js не скачивать. Убедись, что Vite не трогает этот тег при сборке (проверь `dist/index.html`).
- Инициализация `await YaGames.init()` строго по документации.
- `ysdk.features.LoadingAPI.ready()` вызывается ровно тогда, когда главное меню отрисовано и принимает ввод.
- `ysdk.features.GameplayAPI.start()` — когда начинается активный забег и когда он возобновляется после паузы. `stop()` — при паузе, выходе в меню, на экране результата, перед показом рекламы.
- `ysdk.on('game_api_pause' / 'game_api_resume')`: пауза физики, таймеров и всего звука; возобновление, только если игрок сам не ставил паузу.
- Язык: `ysdk.environment.i18n.lang`. Для ru, be, kk, uk, uz — русский, иначе английский. Ручного выбора языка в v1 нет.

### Звук и фокус

- При `visibilitychange` (hidden), `blur`, паузе от SDK и на время любой полноэкранной рекламы весь звук выключен, а физика стоит. При возврате всё восстанавливается.
- AudioContext создаётся или возобновляется по первому жесту пользователя.

### Реклама

- Только `ysdk.adv.showFullscreenAdv` и `ysdk.adv.showRewardedVideo`. Никаких своих «рекламных» окон, имитаций рекламных блоков, сторонних сетей и баннеров.
- Interstitial — только в логических паузах: при переходе с экрана результата к новому забегу или в меню. Никогда во время забега.
- Rewarded — только по нажатию кнопки, на которой явно показано, что будет реклама (иконка ▶ и текст), и что именно игрок получит. Награда выдаётся только в колбэке `onRewarded`. Награда — это бонус: без неё игра полностью проходима.
- На время рекламы игра на паузе и звук выключен. После `onClose` или `onError` всё корректно восстанавливается. Если реклама недоступна, игра не ломается, а кнопка показывает «Реклама пока недоступна».
- Платформа может не показать рекламу, если прошло мало времени с прошлого показа. Это нормально: обрабатывай колбэки и не пытайся обойти ограничение.

### Сохранения

- Храним прогресс в `player.setData` (облако) плюс локальный кэш.
- Сохраняем сразу после каждого значимого действия: новая форма в альбоме, покупка, апгрейд, конец забега, награда, смена настроек. Облачную запись можно откладывать не больше чем на 1 с, но при паузе и скрытии вкладки делать немедленный flush.
- Текущий забег (позиции, тиры, счёт, seed) сохраняется снимком при паузе, скрытии вкладки и каждые 5 с. При следующем запуске предлагаем «Продолжить забег?».
- Играть можно без авторизации, гостевой прогресс сохраняется. Авторизация через Яндекс ID — только по кнопке с объяснением выгоды, например: «Войди, чтобы твой рекорд попал в таблицу и прогресс был на всех устройствах».
- У схемы сохранения есть версия `v`, миграции и тесты на них. Битое сохранение заменяется безопасным дефолтом, игра не падает.

### Экран и управление

- Canvas занимает весь экран, фон рисуем сами. Игровая колонка портретная, по центру: логическая ширина 720, высота адаптируется под экран. В альбомной ориентации и на десктопе по бокам — фон темы, а не чёрная заливка. На десктопе длинная сторона активного поля не больше двух коротких.
- Ресайз и поворот экрана обрабатываются без перезапуска и без потери состояния. Ничего не обрезается и не перекрывается. Нет браузерного скролла и pull-to-refresh: `touch-action: none`, `overscroll-behavior: none`, `user-select: none`, `-webkit-touch-callout: none`, контекстное меню отключено.
- Управление: тач, мышь и клавиатура (←/→ или A/D — двигать, Space/Enter — сбросить). Клавиши определяются по `event.code`, поэтому раскладка не важна. Никаких системных сочетаний клавиш.
- Игра управляется одной рукой, все кнопки не меньше 48 px, devicePixelRatio ограничен значением 2.

### Покупки

- Только через `ysdk.payments`. При старте вызываем `getPurchases()`: расходуемые покупки выдаём и консумируем (`consumePurchase`), постоянные (`no_ads`, `skins_pack`) не консумируем и восстанавливаем из списка.
- Цена всегда показывается с иконкой и названием портальной валюты из SDK (`getPriceCurrencyImage` и данные каталога).
- Список покупок в игре совпадает со списком активных покупок в консоли.
- Для dev-режима — `purchases-catalog.json` в корне проекта.

### Контент и тексты

- Возрастной рейтинг 0+. Никакой политики, религии, магии, ведьм и гаданий, насилия, страшилок, реальных денег и призов.
- Никаких чужих персонажей, брендов и мемов: Roblox, брейнроты, Скибиди, Minecraft, Labubu и подобное — ни имён, ни узнаваемой внешности. Все персонажи наши.
- Нет внешних ссылок и сетевых запросов. Нет интерактивного ИИ внутри игры.
- Нет ввода текста и чата, никакого пользовательского текста, видимого другим.
- Тексты грамотные, все игровые строки переведены на ru и en. Название игры везде одинаковое.

### Сборка

- В корне архива лежит `index.html`, все пути относительные, имена файлов латиницей и без пробелов, архив меньше 100 МБ (наша цель — меньше 5 МБ).
- Нет абсолютных URL на S3 Яндекса.
- В консоли браузера нет ошибок и предупреждений от нашего кода.

## Скрипт `npm run moderation`

Проверяет `dist/` и падает с понятным сообщением, если:

- нет `index.html` в корне, есть пробелы или кириллица в именах файлов, превышен размер;
- тег `/sdk.js` отсутствует или изменён; в коде нет вызовов `LoadingAPI.ready` и `GameplayAPI`;
- в бандле есть `http://` или `https://` (кроме явного whitelist, например строк лицензий), `window.open`, `<a href`, обращения к `localStorage` вне `platform/`;
- наборы ключей в `ru.json` и `en.json` не совпадают;
- покупки в `purchases-catalog.json` не совпадают с `config/iap.ts`.

В конце скрипт печатает ручной чек-лист из раздела 18 диздока.

## Как работать

1. Любая задача больше мелкой правки начинается с плана: что меняю, какие файлы, как проверю. Жди моего «ок».
2. Маленькие шаги: одна фича — один коммит. Сообщения коммитов: `feat: …`, `fix: …`, `chore: …`.
3. После каждого шага запускай `npm run check`. Для визуальных изменений запускай `npm run e2e` и сам смотри получившиеся скриншоты. Нашёл проблему — исправь до отчёта.
4. Никаких заглушек и TODO в фичах, которые ты называешь готовыми. Не уверен — спроси.
5. Веди `docs/PROGRESS.md`: что готово, что в работе, известные баги, принятые решения и почему.
6. Если я прошу что-то, что нарушает требования Яндекса или безопасность детей, скажи об этом прямо и предложи безопасную альтернативу.

## Когда фича считается готовой

- Работает на 360×640, 390×844, 844×390, 768×1024, 1280×720 и 1920×1080; скриншоты лежат в `e2e/__screens__`.
- В консоли нет ошибок, `npm run check` проходит.
- Все строки есть на ru и en.
- Состояние переживает поворот экрана, сворачивание вкладки, показ рекламы и перезагрузку страницы.
